# ros_mujoco

ROS 1 package extracted from `crimson_sim`'s `ros_interface` branch.

It subscribes to real Crimson Dynamixel commands on `/dynamixel_control/sync_write`,
converts raw encoder ticks into the 17D MuJoCo actuator order, and applies the command
to the Crimson MuJoCo model in `src/models/crimson/mjcf/crimson_scene.xml`.

## Conversion

The extracted conversion is in `scripts/ros_mujoco_utils/conversion.py`.

Input forms:

- `SetParam.motorID` + `SetParam.params`: arbitrary motor subsets, using 1-based Dynamixel IDs
- 17 values: full real robot command
- 5 values: frame/body motors only, updates MuJoCo control indices `0..4`
- 12 values: leg motors only, updates MuJoCo control indices `5..16`

Formula:

1. encoder ticks to degrees: `ticks * 180 / 2048`
2. subtract calibrated bias
3. apply sign matrix
4. convert to radians
5. reorder from real motor order to MuJoCo actuator order with `RULES`

## Run

```bash
roslaunch ros_mujoco ros_mujoco.launch
```

Useful args:

```bash
roslaunch ros_mujoco ros_mujoco.launch render:=false
roslaunch ros_mujoco ros_mujoco.launch real_control_topic:=/dynamixel_control/sync_write
```

The node also provides `get_angles` (`ros_mujoco/get_angles`) returning `qpos[7:]`,
matching the original `crimson_sim` interface shape.

## Replay Experiment Energy

`scripts/mujoco_experiment_energy.py` replays `trans_planner/config/experiment.yaml`
inside MuJoCo without publishing to the real robot topics. It reuses:

- `trans_planner/scripts/interpolation.py`
- `trans_planner/scripts/utils/sim2real.py`
- `optimizer/scripts/sim_env.py`
- the same torque-to-energy polynomial from `optimizer/scripts/pareto_optimizer_node.py`
  in legacy mode
- `scripts/ros_mujoco_utils/energy_calibration.py` in calibrated modes

Run:

```bash
python3 src/ros_mujoco/scripts/mujoco_experiment_energy.py --num-experiments 1
```

The result is saved under `runs/mujoco_experiment_energy_<timestamp>.json` by default.
Use `--no-settle` to skip the hold phase, or `--render` to show MuJoCo.
Use `--output <path>` for deterministic artifact names.

Energy modes:

- `--energy-mode legacy` keeps the historical torque-to-current polynomial.
  This is the default for backward compatibility.
- `--energy-mode calibrated_no_residual` uses the fitted aggregate base plus
  leg-torque model without per-transition residuals.
- `--energy-mode calibrated` uses the fitted aggregate model and explicit
  transition residuals from the real transform-loop dataset.
- `--energy-mode dynamic_calibrated` adds the dynamic 50 Hz interval
  offsets for all 16 command intervals, including the final `mu2->mu1` window.

For the current sim-to-real transform-loop calibration, run:

```bash
python3 src/ros_mujoco/scripts/mujoco_experiment_energy.py \
  --num-experiments 10 \
  --energy-mode dynamic_calibrated \
  --log-rate 50 \
  --output runs/mujoco_experiment_energy_dynamic_calibrated_full10_50hz.json
```

The current calibrated model assumes the MJCF gains in
`src/models/crimson/mjcf/crimson_stand_legInit_forSimOnly.xml`: frame actuators
use `kp=30, kv=2.6087`, while leg actuators use `kp=10, kv=0.869565`
(`kv_divisor=11.5`).

The JSON keeps the same experiment recording structure as
`trans_planner/scripts/experiment.py`:

- `experiments[*].records["/crimson_control/transform"]`
- `experiments[*].records["/crimson_control/transformed"]`
- `experiments[*].records["/dynamixel_control/log"]`
- `experiments[*].sync_write_commands` for the exact per-frame `SetParam`
  commands generated by the original experiment flow

## Calibration Workflow

The detailed calibration record is
`runs/real_result/trans_loop_real/calibration_report.md`. Real power is
integrated from the 17 motor voltage/current columns as
`sum(U_i * abs(I_i))`. The real reference CSV logs and generated replay JSON
are not stored in the code repository; provide them to the comparison script
with `--real-csv-dir` and `--sim-json`.

Useful scripts:

- `runs/real_result/trans_loop_real/analyze_trans_loop_energy.py` analyzes the
  real CSV runs and writes the real mean/std plot and summary.
- `runs/real_result/trans_loop_real/diagnose_mujoco_energy.py` compares legacy
  signed-torque and abs-torque energy calculations against the saved replay.
- `runs/real_result/trans_loop_real/scan_mujoco_model_variants.py` scans floor
  friction, contact/gravity toggles, and actuator gain variants.
- `runs/real_result/trans_loop_real/fit_energy_calibration.py` fits aggregate
  power models from real interval power and MuJoCo torque features.
- `runs/real_result/trans_loop_real/replay_calibrated_from_json.py` rewrites a
  saved legacy full10 replay into `runs/mujoco_experiment_energy_calibrated_full10.json`.
- `runs/real_result/trans_loop_real/analyze_trans_loop_json.py` plots the
  calibrated JSON U/I logs.
- `runs/real_result/trans_loop_real/plot_real_sim_energy_comparison.py`
  compares the calibrated 50 Hz real/sim traces, exports the comparison plot,
  and writes interval/phase energy summaries.
- `runs/real_result/trans_loop_real/apply_interval_residual_calibration.py`
  applies the 16 interval-level 50 Hz residuals to a dynamic replay trace.
- `runs/real_result/trans_loop_real/scan_mujoco_dynamic_response.py` scans
  dynamic actuator gains against real qpos/P[] phase and power metrics.
- `runs/real_result/trans_loop_real/fit_phase_aware_calibration.py` and
  `runs/real_result/trans_loop_real/compute_50hz_calibration_metrics.py` are
  diagnostics used to cross-check phase-split and first-15/first-16 summaries.

The final 16-interval dynamic 50 Hz calibration-set comparison is shown below.
Energy values are the mean plus or minus the sample standard deviation across
ten real-robot trials and ten MuJoCo replay records, respectively (`ddof=1`):

```text
total energy:       real=3.776 +/- 0.026 kJ, sim=3.776 +/- 0.006 kJ
transform energy:   real=1.681 +/- 0.021 kJ, sim=1.629 +/- 0.008 kJ
sustain energy:     real=2.095 +/- 0.025 kJ, sim=2.147 +/- 0.010 kJ
transform duration: real=1.371 s, sim=1.332 s, MAE=0.168 s
interval power:     MAE=0.555 W, RMSE=1.827 W, bias=-0.357 W, corr=0.995
```

The older first-15-interval calibration is retained in the report as historical
context. The residual terms are fitted for this transformation-loop dataset;
treat them as an experiment calibration layer, not as a general physical
friction model for all future Crimson motions.
