# Requirement-Vector Model Card

## Output contract

All methods predict the same ordered seven-dimensional vector:

| Field | Meaning | Domain |
| --- | --- | --- |
| `wp_m` | required passage width | non-negative meters |
| `hp_m` | required passage height | non-negative meters |
| `dp_m` | required passage depth | non-negative meters |
| `hs_m` | required step/obstacle height | non-negative meters |
| `fl` | load-related task factor | `[0, 1]` |
| `fi` | inspection-related task factor | `[0, 1]` |
| `fp` | packing-related task factor | `[0, 1]` |

## Full-MIMA teacher

The frozen teacher used an approximately 4B-parameter InternVL multimodal
backbone and exposed the common `/predict` schema. The recorded checkpoint
identifier is `checkpoint-650`; the SHA-256 of its recorded `config.json` is:

```text
e2c0abf60df5b6c4f8b70f60861ff2a371693e230978b2783a161f0fc3a09d39
```

The checkpoint, requirement-vector prompt, sensor preprocessing service, and
server launcher are not present in the available release assets. Generic
InternVL code in the parent directory is therefore not, by itself, a local
reproduction of the paper-specific teacher.

## MLLM-distilled: Teacher-only ET32

The adopted compact student was trained from requirement vectors generated by
the frozen Full-MIMA teacher. Original targets were excluded from the student
training objective and retained only for offline evaluation.

| Property | Recorded value |
| --- | --- |
| Model identifier | `strict_student_teacher_only_et32_s32768` |
| Estimator | multi-output ExtraTrees ensemble |
| Number of trees | 32 |
| Input | deterministic 85-D sensor-summary vector |
| Feature implementation identifier | `distill_sensor_summary_v2_sampled` |
| Sensor-element sampling limit | 32,768 |
| Training split size | 978 outer-training samples |
| Output | seven-dimensional `v_r` |
| Model source commit recorded by deployment bundle | `39647f66c5b9bacb308023344f95939e95133308` |

The 32,768 value limits sensor elements sampled during feature extraction; it
is not the number of training samples. The term Teacher-only refers only to
the targets used to supervise this final student. Original targets were still
available for offline evaluation and earlier architecture selection, so the
entire development process should not be described as label-free.

## Conventional replacement baselines

The RF, DT, and GBT rows replace only the MLLM requirement-vector generator.
Their downstream cVAE generator, energy optimizer, and controller remain
unchanged in the system-level experiment.

Unlike MLLM-distilled, these methods use the released deterministic 16-feature
adapter. The fitted bundle records 202 training samples and `random_state=42`.

| Method | Estimator |
| --- | --- |
| w/o MLLM -> RF | `RandomForestRegressor(n_estimators=200, max_depth=8, min_samples_leaf=1)` |
| w/o MLLM -> DT | `DecisionTreeRegressor(max_depth=6, min_samples_leaf=1)` |
| w/o MLLM -> GBT | seven-output wrapper around `GradientBoostingRegressor(n_estimators=100, learning_rate=0.05, max_depth=2)` |

Environmental outputs are clipped to non-negative values and task-factor
outputs are clipped to `[0, 1]` after prediction. The weight hashes are stored
with the files under `models/baselines/`.

## Intended use and limitations

These assets support requirement-vector inference and method auditing for the
MIMA study. They are dataset-specific research components, not universal
perception models. They should not be used for safety-critical control without
independent validation, and results obtained from another service checkpoint,
feature implementation, split, or model hash must not be presented as the
reported experiment.
